## 核心铁律:跨章银行短信 + 系统状态必须 1:1 接续

**触发**: 任何章节的 `【工商银行】` 短信末余额,必须 = 上一章末余额 + 本章新增花销 - 返利入账。

## 5 步数字对账 SOP(每章产出后必跑)

```
Step 1: 提取本章所有"花冤"事件
        - 转账金额(支出)
        - 系统返利(收入)
        例:Ch6 = 转 1000 + 转 1 元 + 转 32000 + 返 50万 + 返 500 + 返 1600万

Step 2: 找上一章末余额基准
        例:Ch5 末 18,175,000 (1318 + 5000×500 - 0.5 + 250万)

Step 3: 算本章末余额
        18,175,000 - 1000 + 500,000 - 1 + 500 - 32000 + 16,000,000 = 34,143,500

Step 4: 短信内"余额"必须与 Step 3 一致
        ❌ 错:18,175,000 - 1,000 = 18,174,000 (漏返利)
        ✅ 对:18,174,000 + 500,000 = 18,174,500 (返利后)

Step 5: 系统框的"累计花销/累计返利/卡余额"必须接续
        例:Ch6 末"累计花销:5,887,000元" = Ch5 末 5,855,000 + Ch6 新增 32,001 元
```

## 4 种常见 BUG + 修复公式

### BUG 1: 数字凭空回退
**症状**: Ch5 末 1380万 → Ch6 末 141 万
**根因**: 我把 Ch4 末数字"1,308,000"当 Ch6 末数字用(写剧本时忘了 Ch5 累积)
**修复公式**: Ch6 末 = Ch5 末 + (本章新增花销) - (本章新增返利)
**自动检测**:
```python
# 跨章余额校验
prev_end_bal = 18_175_000  # Ch5 末
events_ch6 = [('out', 1000), ('in', 500_000), ('out', 1), ('in', 500), ('out', 32000), ('in', 16_000_000)]
cur_end_bal = prev_end_bal + sum(in_amt for typ, in_amt in events_ch6 if typ=='in') - sum(out for typ, out in events_ch6 if typ=='out')
# = 34,143,500 ✓
```

### BUG 2: 系统框"累计花销/返利"漏单位
**症状**: Ch7 系统"累计亏损:5.5万"(实际应是 5,898,244元 = 590万)
**根因**: 漏写"万"单位,或者用"<单位>"+ "数字"没统一
**修复公式**: 数字统一用阿拉伯数字 + 元单位,不要再用"5.5万"这种简写

### BUG 3: 末段"他儿子有 X 万"数字与短信不一致
**症状**: Ch6 末"她儿子有 1380 万"但实际卡里 34,143,500 = 3414 万
**根因**: 末段用粗略整数,没跟短信余额同步
**修复公式**: 末段数字必须 = 短信末余额(粗略整数)

### BUG 4: 主角"卡里"vs"5亿返利"混用
**症状**: Ch4 写"卡里 1500 万"实际是 1318 万
**根因**: 混淆"卡余额"和"累计返利"
**修复公式**:
- **卡余额** = 实际银行账户里的钱 (主角能花的钱)
- **累计返利** = 系统累计给主角返的钱(花 1 返 500,累计返利 = 累计花销 × 500)
- 两者是不同概念,不能混用

## 6 步校验代码(必跑)

```python
def verify_chapter_balance(prev_bal, events, chapter_name):
    """events = [(type, amount), ...]"""
    cur_bal = prev_bal
    for typ, amt in events:
        if typ == 'out': cur_bal -= amt
        elif typ == 'in': cur_bal += amt
    return cur_bal

# 跑每一章
ch5_balance = verify_chapter_balance(
    prev_bal=13_180_000,  # Ch4 末
    events=[('out', 5000), ('in', 2_500_000)],
    chapter_name='Ch5'
)
# = 18,175,000 ✓

ch6_balance = verify_chapter_balance(
    prev_bal=18_175_000,  # Ch5 末
    events=[
        ('out', 1000), ('in', 500_000),
        ('out', 1), ('in', 500),
        ('out', 32000), ('in', 16_000_000)
    ],
    chapter_name='Ch6'
)
# = 34,143,500 ✓
```

## 教训(本会话 5+ 处 BUG 实踩)

1. ❌ 写剧本时拿 Ch4 末"1,308,000"作为 Ch6 起点(忘了 Ch5 累积 1380 → 1817)
2. ❌ 删 Ch5 旧版 + 写 Ch5 v4 时把 Ch4 末数字"1318 万"误填为"1380 万"(原 Ch4 末"1318"误读为 Ch5 末"1380")
3. ❌ Ch13 银行短信余额 14,214,133,实际 Ch10 末 15,026,913.50 - 1.5 = 15,026,912.00 + 150 = 15,027,062.00
4. ❌ Ch7 系统框"累计亏损 5.5万"漏单位(应是 5,898,244 元 = 590 万)
5. ❌ Ch7 系统框"累计返利 2750万"与 Ch6 末"2.95亿"差 10 倍

## 修复策略

1. **每章写完后,跑 6 步数字校验**(上面代码)
2. **不通过校验 → 立即 patch,不准推下一章**
3. **数字统一用阿拉伯数字 + 元单位**(不要再用"X 万"简写,容易抄错)
4. **章节内"卡里 X 万"必须 = 银行短信末余额**(粗略整数)
5. **章节内"累计花销/累计返利"必须 = 系统框数字**
