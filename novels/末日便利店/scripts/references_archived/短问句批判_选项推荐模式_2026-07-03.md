# 用户"短问句批判"模式 — 选项+推荐,不直接动笔

> 来源: 用户2026-07-03原话"卡里就5块钱,还全花了买表,合理么?" + "怎么写的?一点都不符合逻辑"
> 触发: SKILL.md → 🚨 用户"短问句批判"模式 (2026-07-03 焊死)

---

## 🎯 1. 模式定义

用户用**短问句**对章节/设定/逻辑提出质疑时,期望AI:
- ✅ **承认问题**
- ✅ **列 2-3 个改法 + 推荐 + 理由**
- ❌ **不动文件**(等用户拍板)

---

## 📝 2. 触发信号词典

任何包含以下特征的问句 = **短问句模式**:
- **结尾是"?"**(问句)
- **没动词"做/改/加/执行"**
- **包含评价词**: 合理 / 逻辑 / 符合 / 离谱 / 尴尬 / 漏洞

**典型例子**:
- "卡里就5块钱,还全花了买表,合理么?"
- "怎么写的?"
- "一点都不符合逻辑,优化下"
- "是不是太离谱?"
- "你怎么看?"
- "这样写读者会怎么看?"
- "哪里不对?"
- "是不是有毒?"

---

## 🛠️ 3. 正确回复模板

```markdown
你说得对。[问题1-2句话简述,不辩解]。

3个改法:
A) [改法一] — 优点:[X]/ 缺点:[Y]
B) [改法二] — 优点:[X]/ 缺点:[Y]  ← 我推荐,因为[理由简述]
C) [改法三] — 优点:[X]/ 缺点:[Y]

你拍板?
```

**回复长度限制**: ≤ 300字。**严禁**:
- ❌ 长篇辩护(用户就是问"合不合理",不是要你解释为啥合理)
- ❌ 立即动手重写
- ❌ 堆一堆不相干的修复动作

## 🚫 4. 反例(本会话真的踩过 / 差点踩)

### 反例1:用户问"合理么?",AI立即跑去改文件
```
用户: 卡里就5块钱,还全花了买表,合理么?
[DS-0] 立刻跑去 read_file + 写新版 Ch1 + 跑检测器 + 贴全文
```
**错在哪**:用户没说要改,只是问。AI 抢先操作,等用户被惊到"我没让你改啊"

### 反例2:AI 长篇辩护"这其实是合理的"
```
用户: 卡里就5块钱,还全花了买表,合理么?
[DS-0] (3000字解释)这个设定有深刻的隐喻意义,5块钱在番茄设定里是父亲遗产,所以花5块买怀表是合理的情感闭环,与金手指机制一致...
```
**错在哪**: 用户问"合理么"是在**质疑**,AI 应承认或讨论,不是**辩护**

### 反例3:AI 只承认问题不给方案
```
用户: 卡里就5块钱,还全花了买表,合理么?
[DS-0] 嗯,你说得对,是不太合理。
```
**错在哪**: 用户下一步还得问"那怎么改?" — 浪费一轮

### 反例4:AI 给方案但没推荐
```
用户: 卡里就5块钱,还全花了买表,合理么?
[DS-0] 3个改法:
A) 改成起步50块
B) 改成起步5块但加父亲遗产背景
C) 改成保留5块+当日系统给1万启动资金
```
**错在哪**: 用户得自己判断哪个好,想"我就问你AI你觉得哪个对"— 用户原话"你再优化下"暗示AI要主动判断

### ✅ 正例(本会话最后那个回复)
```
[DS-0] 用户: 卡里就5块钱,还全花了买表,合理么?

✅ 承认问题 + 3 个改法 + 推荐 B

你说得对,卡里5块全花光确实有问题。
3个改法:
A) 起步50块 — 简单但冲突 bible 设定
B) 保留5块,加父亲遗产背景 — 情感张力max,F001伏笔加分
C) 5块买表+系统当日给1万启动资金 — 机制合理但破坏"花冤"规则
我推荐 B,因为[理由:双重伏笔,情感闭环,机制不破坏]
拍板?
```

## 🔄 5. 与其他模式的区分

| 触发词类型 | 模式 | AI动作 |
|---|---|---|
| "改吧"/"执行吧"/"加吧"/"重做Ch3" | **立即执行** | 直接动文件,确认后即写 |
| "合理么?"/"怎么写?"/"符合逻辑么?" | **短问句批判** | 方案+推荐,**不动文件** |
| "流程优化"/"整套优化"/"系统化" | **元级反馈** | 修技能/工具,**不动章节** |
| "停" | **暂停** | 立即停手,**停在想方案阶段** |
| "继续"/"下一个" | **继续** | 接上一轮任务 |

**判断捷径**(对话开场):
1. 是否有动作动词 → 立即执行
2. 是否元词(流程/系统/整套) → 元级反馈
3. 是否问句带评价词 → 短问句批判
4. 是否"停"/"别了" → 暂停
5. 是否"继续"/"下一个" → 继续

## 📚 7. 实战案例库(本会话2026-07-03)

### 案例 1: 番茄 Ch1 重写请求
**用户**: "重写番茄吧,简介也给我"
- 模式: **立即执行**(有"重写"动词)
- 正确动作: 直接动 files + 跑 detector + 简介

### 案例 2: 番茄简介 5 块钱质疑
**用户**: "你再看下番茄简介,卡里就5块钱,还全花了买表,合理么?"
- 模式: **短问句批判**
- 正确动作: 承认 + 3 改法(A/B/C)+ 推荐 B + 等用户拍板

### 案例 3: 流程优化
**用户**: "番茄Ch1这么多逻辑漏洞,你怎么写的?一点都不符合逻辑,整套写小说的流程你再优化下"
- 模式: **元级反馈**(有"整套流程"等元词)
- 正确动作: 根因审计 + 报告用户 + 修工具 + 修章节 + 验证

### 案例 4: 简介方案 B 拍板
**用户**: "一起改吧用B"
- 模式: **立即执行**(有"改吧用B" 选择动作)
- 正确动作: 立即动 Ch1 + 简介

## 🎓 8. 训练要点(给未来的 DS-0)

1. **不要预设用户要"立即执行"**。问句 ≠ 执行授权。
2. **承认问题 ≠ 自我贬低**。承认"卡里5块全花光确实有问题"不是认错,是诚实。
3. **推荐必须有理由**。"我推荐X" 后面写"因为Y",用户才知道AI真的想清楚了。
4. **短问句**还要注意:**不要堆数据**,不要长篇大论。
5. **耐心等拍板**。用户拍板后才动文件,这是**纪律**不是胆怯。

---

## 📎 9. 与检测器的关系

这种模式**不需要**专门 detector — 它是**对话层行为规则**,不是**章节内容规则**。

但有一条**章节内容规则**会用到这套原则:
- 番茄 Ch1 重写后,**重新跑 detector 看哪些维度还有问题** → 用"短问句"模式报告用户"X 维度 60 分,3 改法 + 推荐",让用户拍板

**完整联动**:
1. 用户对话 → 短问句模式 → 3 改法 + 推荐
2. 用户拍板 → 立即执行模式 → 动文件
3. 动完 → 跑 detector → 看分数
4. 分数低 → **短问句模式** → 又 3 改法 → 又拍板
5. 循环,直到每章 ≥ 75 分 7/8 维度

这种**"短问句 ↔ 立即执行"循环**是用户长期工作模式,不是单次事件。
