# 日期违规检测器范围陷阱 (2026-07-04 焊死)

## 致命陷阱

**检测器正则查"全文件",把剧情中的"12月30日开庭"、"07月07日到账"等具体日期全误判违规,导致作者误以为有违规,实际没有。**

## 真实复现 (2026-07-04)

初版检测器正则:
```python
# ❌ 错 — 查全文件
violations = re.findall(r'(七月X日|七月\d+日|Day \d+|X月X日|\d+月\d+日|早上九点|晚上[一二三四五六七八九十]点|...)', c)
```

起点 Ch7 重写后(1897字,日期开头已合规),全文件检测仍报 7 处违规:
- pos=285: "12月30日见" (新闻引用)
- pos=413: "12月30日开庭" (新闻引用)
- pos=854: "开庭12月30日" (剧情对话)
- pos=883: 同上
- pos=1046: "12月30日之后" (剧情)
- pos=1046+289: 同上
- pos=1560: "07月07日15:00" (银行短信)

**全部是剧情中的合理日期引用,不是章节开头违规**。但正则 `\d+月\d+日` 把它们全捕获。

## 修复 (焊死)

**只查首段(章节开头),不查全文**:

```python
def check_date_violation(content):
    """只查章节开头第一段, 不查全文"""
    parts = content.split('\n\n', 1)
    first_block = parts[1][:200] if len(parts) > 1 else content[:200]
    
    violations = re.findall(
        r'(七月X日|七月\d+日|Day \d+|X月X日|\d+月\d+日|早上九点|'
        r'早上[一二三四五六七八九十]点|晚上[一二三四五六七八九十]点|'
        r'下午[一二三四五六七八九十]点|中午[一二三四五六七八九十]点|'
        r'上午[一二三四五六七八九十]点)',
        first_block  # ← 只查首段
    )
    return len(violations) > 0
```

## 为什么只查首段

**用户原话**: "开头日期时间太尴尬了, 修复好"

- "**开头**" — 关键词是首段
- 剧情中的 "12月30日开庭" / "07月07日到账" / "Day 3 故事背景" — 这些是合理剧情内容
- 真违规 = 章节首段第一句就是 "X月X日, 早上X点" 模式

## 适用范围

✅ **应判违规的**:
- "七月七日,早上九点。林北舟被..." (开头)
- "Day 4,晚上八点。顾行舟在..." (开头)
- "第三天,早上九点。主角..." (开头)

❌ **不应判违规的** (剧情中合理出现):
- 银行短信: "07月07日15:00收到转账"
- 法庭公告: "12月30日开庭"
- 主角回忆: "那是3年前,4月15日"
- 主角计划: "明天,8月20日,我要..."

## detector 3 件套 (焊死到代码)

1. **正则**: `r'(七月X日|七月\d+日|Day \d+|X月X日|\d+月\d+日|早上九点|早上[一二三四五六七八九十]点|晚上[一二三四五六七八九十]点|下午[一二三四五六七八九十]点|中午[一二三四五六七八九十]点|上午[一二三四五六七八九十]点)'`
2. **范围**: `c[:300]` 或首段(取前 `'\n\n'` 之前)
3. **输出**: PASS (首段无日期) / FAIL (首段有日期,输出前 30 字)
