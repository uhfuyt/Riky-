## 二、跨分类生产必须解决的需求

### 2.1 CLI 必须加的 flag

```bash
# 现状
python3 novelforge.py status qidian
python3 novelforge.py next qidian
python3 novelforge.py chapter qidian 2

# 必须升级为
python3 novelforge.py status --book=qidian --genre=都市
python3 novelforge.py next --book=qidian --genre=都市
python3 novelforge.py chapter --book=qidian --genre=都市 --num=2
# 或开新书:
python3 novelforge.py init --book=玄幻x --genre=玄幻 --platform=qidian
```

### 2.2 Codex 数据模型必须扩展的字段

| 字段 | 现状 | 升级后 |
|---|---|---|
| `genre` | 无 | 枚举: 玄幻/历史/军事/科幻/无限流/都市 |
| `subgenre` | 无 | 子赛道(玄幻=修仙/玄幻/修真/...) |
| `power_system` | 单一返利数值 | 多态: 数值型/境界型/科技等级/副本属性 |
| `worldview_constraints` | 简单 tag | 完整文件 `references/世界观锚点_{genre}.md` |
| `red_line` | 单一 list | 按分类的多个独立 red_line 列表 |
| `hooks_pattern` | 5 种通用模式 | 8-10 个分类专属 hooks(见下) |

### 2.3 力量体系多态化

```python
# v0.1 (都市单态)
codex.power = {
  "type": "cash",
  "value": 518000,
  "history": [...]
}

# v0.2 (多态)
codex.power = {
  "system_type": "境界",  # 境界|科技|副本|数值|军衔
  "current": "金丹期",    # 不同系统不同值类型
  "sub_level": 3,
  "next_required_xp": 50000,
  "history": [...]
}
```

### 2.4 Index 必须升级为分类路由

```python
# v0.1
novelforge/codex.json  # 单 book

# v0.2
novelforge/
├── codex/{book_id}.json
├── bible/{book_id}.md
├── power_systems/
│   ├── 玄幻.json  # 境界表
│   ├── 科幻.json  # 科技等级表
│   ├── 历史.json  # 朝代官职表
│   ├── 军事.json  # 军衔表
│   ├── 无限流.json # 副本属性表
│   └── 都市.json  # 数值表
├── genre_metadata/
│   ├── 玄幻_meta.json
│   ├── 历史_meta.json
│   ├── 军事_meta.json
│   ├── 科幻_meta.json
│   ├── 无限流_meta.json
│   └── 都市_meta.json
└── README_genre.md  # 6 种力量体系的 hook/sandbox/红线索引
```

### 2.5 Plausibility 检测器必须分类化

```python
# v0.1 (单一类型)
plausibility.check(genre='default', content)

# v0.2 (按分类选 detector)
plausibility.check(genre='玄幻', content)  # 必查境界一致性
plausibility.check(genre='科幻', content)  # 必查时间线
plausibility.check(genre='无限流', content) # 必查副本规则
```

## 三、本次会话触发的"教训"(迁移到 NovelForge)

### 教训1: 子Agent 在写文件前要先看 SKILL 已有的旧版本
- 本次写了 3 个 Agent 同时跑玄幻/科幻/无限流
- 跑的时候已发现 SKILL references/ 下有现成的 6-7K 薄版
- 子Agent 写的 8000 字完整版会**直接覆盖**,避免重复
- **未来**: NovelForge 的 `init` 命令必须先扫 `_knowledge_base/` 和 `references/`,**有就用, 没有才跑子Agent**

### 教训2: 反爬是 server-side 的,不是工具问题
- 我以为 curl/jina/playwright 总有一个能爬起点
- 实际 server IP (100.90.63.122) 被反爬死防
- 唯一兜底: 用户 0 手动 patch 数据
- **未来**: NovelForge 加 `data/import_url {url}` 命令 = 让用户粘贴榜单 HTML/text,我解析入库

### 教训3: 用户"分类学习"指令 = 长期资产,不是临时任务
- 用户原话 "**以后写每个分类的书,你都有爆款框架**"
- 这是要求建永久知识库,不是产一次性手册
- **未来**: NovelForge 顶部加 `_knowledge_base/` 目录 + git LFS(避免文件超 100M)

## 五、数据流 (v0.2 升级后)

```
用户开新坑 (任意分类)
    ↓
novelforge.py init --book={X} --genre={Y} --platform={Z}
    ↓
load _knowledge_base/{Y}/{6 文件}
    ↓
prompt user: "选子赛道?" (基于 references/头部评测)
    ↓
user: "传统修仙/无限流主神/..."
    ↓
novelforge.py init 生成 codex/{X}.json
    ↓
novelforge.py bible 生成 bible/{X}.md (引用力量体系)
    ↓
novelforge.py chapter ... → 直写 MiniMax → audit → publish
```
