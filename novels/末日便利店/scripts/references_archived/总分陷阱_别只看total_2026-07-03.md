# 总分陷阱 — 别只看 total(2026-07-03 焊死)

> 来源: 本会话番茄Ch1 audit 跑出 total=89.7(看着及格),实际 level_curve_score=60(严重拖后腿,但被其他高分维度"摊薄"了)。
> 用户原话:"番茄Ch1这么多逻辑漏洞,你怎么写的?一点都不符合逻辑"
> 根因不仅是 Ch1 文本,而是 audit 的 accept 逻辑只看了 total 没看各维度 → 我自己也以为 Ch1 "差不多能过",实际 level_curve 维度已经报警。

## 陷阱本质

**加权总分容易被"摊薄"** —— 哪怕某一维度 0分,只要其他维度都 90+,total 仍能上 80+:

```
8维加权, total = 0.20*math + 0.13*inf + 0.12*lvl + 0.10*time + 0.12*cause + 0.08*rule + 0.10*char + 0.15*open

番茄Ch1整改前分数:
  math=100, inf=85, lvl=60, time=90, cause=90, rule=95, char=90, open=0
  total = 0.20*100 + 0.13*85 + 0.12*60 + 0.10*90 + 0.12*90 + 0.08*95 + 0.10*90 + 0.15*0
        = 20+11.05+7.2+9+10.8+7.6+9+0 = 74.65  ← 这是整改前
        (本来 total 还应更低,但通胀因子让 lvl 和 open 都按 60/0 上摊)
  
  整改后 math=100, inf=85, lvl=90, time=90, cause=90, rule=95, char=90, open=100
  total = 0.20*100 + 0.13*85 + 0.12*90 + 0.10*90 + 0.12*90 + 0.08*95 + 0.10*90 + 0.15*100
        = 20+11.05+10.8+9+10.8+7.6+9+15 = 93.25 ← 这是整改后 ✅
```

**关键观察**: open 从 0 涨到 100, total 只涨 ~18 分。lvl 从 60 涨到 90, total 涨 ~3.6 分。说明 **单维高分/低分会被摊薄**,看上去 total 80+ 还行的 Ch1,**可能某一维已经 0 分**。

## 8 维度阈值表(任一维 < 阈值即拒收)

| 维度 | 阈值 | 低于阈值意味着什么 |
|---|---|---|
| **math_score** | ≥ 85 | 数字闭环破了,读者立刻弃书 |
| **inflation_score** | ≥ 70 | 单章资产涨 20 倍,数字通胀 |
| **level_curve_score** | **≥ 85** | **等级阈值或倍数错位**(本次番茄就是栽在这) |
| **time_logic_score** | ≥ 80 | 一天塞 5+ 时段事件,剧情赶 |
| **causality_score** | ≥ 70 | 反派出招但主角没应对(单章内) |
| **rule_score** | ≥ 85 | 主线触碰金手指禁区,违规下架 |
| **character_score** | ≥ 80 | 主角言行不符合人设 |
| **opening_format_score** | **≥ 85** | **章节开头 7 禁违规**(本次番茄就是栽在这) |
| **total** | ≥ 85 | 加权总分 |

**accept 铁律**:
- ✅ `total ≥ 85` **且** 8 维度全部 ≥ 阈值 → accept
- ❌ `total ≥ 85` 但**任一维低于阈值** → 拒绝 + 给 fix 指引 + rerun
- ❌ `total < 85` → 拒绝 + 给 fix 指引

## accept_audit() 标准实现(给 novelforge.py 用)

```python
DIMENSION_THRESHOLDS = {
    'math_score': 85,
    'inflation_score': 70,
    'level_curve_score': 85,
    'time_logic_score': 80,
    'causality_score': 70,
    'rule_score': 85,
    'character_score': 80,
    'opening_format_score': 85,
}
TOTAL_THRESHOLD = 85

def accept_audit(report):
    """返回 (accept: bool, reasons: list)"""
    reasons = []
    
    # 1. 检查总分
    if report['total'] < TOTAL_THRESHOLD:
        reasons.append(f"总分 {report['total']:.1f} < {TOTAL_THRESHOLD}")
    
    # 2. 检查每一维度
    for dim, threshold in DIMENSION_THRESHOLDS.items():
        score = report.get(dim, 100)
        if score < threshold:
            reasons.append(
                f"🚨 {dim}={score} < 阈值{threshold} → 必须修复后重测"
            )
    
    # 3. 检查硬告警(opening_format_failed 是强制 FAIL)
    if report.get('opening_format_failed'):
        items = report.get('opening_format_issues', [])
        reasons.append(f'🚨 开篇格式违规:{", ".join(items)}')
    
    return len(reasons) == 0, reasons


# 用法:
report = plausibility.check('fanqie', chapter_text, ch_num=1)
ok, reasons = accept_audit(report)
if not ok:
    print('章节不通过, 必须修复:')
    for r in reasons:
        print(f'  - {r}')
    raise ValueError('Audit failed')
```

## 本会话真实数据(2026-07-03)

番茄 Ch1 audit:

| 步骤 | total | 隐藏的拖后腿维度 | 我的判断 | 正确判断 |
|---|---|---|---|---|
| 整改前 | 89.7 | open=**0**, lvl=**60** | "差不多能过" ❌ | accept 拒收 🚨 |
| codex 整改后 | 93.2 | open=100, lvl=**90** | accept ✅ | accept ✅ |
| 整套(章节+codex)后 | 93.2 + 8维全过 | — | accept ✅ | accept ✅ |

**教训**: 一开始我看到 89.7 就"差不多能过",没看每维度分数 → 用户验收时才说"逻辑漏洞多"。**规则化**: 任何 audit 必须用 `accept_audit()` 而非"看 total"。

## 给 DS-0 的自检清单(每次 audit 后)

- [ ] 跑完 `plausibility.check()` 后立刻跑 `accept_audit(report)`
- [ ] 不要看 `total` 字段,直接看 `accept` 返回值
- [ ] 任何维度 < 阈值 → 必须修复该维度相关的内容/工具,**不能"差不多就过"**
- [ ] 历史章节 audit 通过 ≠ 当前章节 audit 通过(每次独立)
