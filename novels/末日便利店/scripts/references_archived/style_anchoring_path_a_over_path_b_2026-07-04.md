# 路径A 强制 — 风格锚定的元教训 (2026-07-04 焊死)

> **用户原话 (2026-07-04)**: "番茄跟起点前面的内容, 你续写的第四章跟第七章, 不管是排版还是内容都不相关"
> **根因**: 用路径 B (aipro gemini-3.1-flash-lite API) 写续写章节, 跟路径 A (MiniMax 对话直写) 写的头几章风格完全不同.
> **结论**: **写正文 = 永远用路径 A**. 路径 B 只用于 audit / 调研 / 写短摘要, 不写 1000+ 字的小说正文.

这是本会话**最关键的元教训**, 比任何技术 bug 都重要.

---

## 路径 A vs 路径 B — 4 维度对比

| 维度 | 路径 A (MiniMax 对话直写) | 路径 B (aipro API) |
|---|---|---|
| **风格一致性** | ✅ 同上下文, 跟头几章风格100%一致 | ❌ 不同模型, 风格漂移 (gpt vs gemini vs claude 各有"AI味") |
| **preamble 风险** | ✅ 0 (对话窗口不输出"我是AI") | ❌ 5-30% (gemini 在多约束下必出 "你好我是Antigravity") |
| **token 成本** | ✅ 0元 | ❌ 5-15元/30万字 |
| **速度** | 🟡 看上下文长度 (10-30秒/章) | ✅ 5-10秒/章 (API并发) |
| **伏笔接续** | ✅ 同一上下文, 不会忘 | ⚠️ 靠 prompt 喂入, 模型可能忽略 |
| **人设锁定** | ✅ 同一会话, 不会乱起名 | ⚠️ 靠 codex.chapters_meta 喂入, 模型可能编 |
| **场景接续** | ✅ 同一上下文, 自然过渡 | ⚠️ 靠"最近 N 章原文尾段"喂入, 但格式不同 |

## 用户反馈的具体问题 (本会话)

用户原话: "**番茄跟起点前面的内容, 你续写的第四章跟第七章, 不管是排版还是内容都不相关**"

具体表现 (对比 Ch1-3 vs 重生成的 Ch4/Ch7):

| 维度 | 起点 Ch1-3 (MiniMax 手写) | 起点 Ch7 (gemini API 写) — **修复前** |
|---|---|---|
| **标题行** | `# 亏钱返利` | `"顾哥！你冷静点..."` 直接对话当首行 |
| **开头风格** | "七月的X, 热得像蒸笼..." 景物 | "你好, 我是Antigravity..." AI 助手 |
| **段落结构** | 每段 1-3 句, 句子短 | 每段 5-8 句, 句子长 |
| **"。" vs "!"** | 大量句号, 感叹号少 | 大量感叹号+问号 |
| **人设语气** | 嘴贱/自嘲/平实 | 装 X / 中二 / 浮夸 |
| **配角不连贯** | 钱小宝一直在 | 突然出现"陌生人""黑色符号"等 Ch1-3 没的元素 |

番茄 Ch1-3 → Ch4 同样的问题.

## 决策矩阵 (何时用哪个)

```
写章节正文 (≥1000字) → 永远用路径 A (MiniMax 直写)
短摘要 / 调研 / 数据 → 路径 B OK
audit / 测试 / debug → 路径 B OK
早期实验 / 试错 → 路径 B OK (成本低, 迭代快)
头三章已发布, 续写 Ch4+ → 必走路径 A (风格一致)
```

### 何时路径 B 仍可用

1. **章节摘要/梗概生成** (500字内, 不是正文)
2. **伏笔表/角色表的 JSON 生成** (struct data, 不是正文)
3. **批量调研** (查榜单, 分析竞品)
4. **audit 守门员** (审计已写好的章节)
5. **用户明确说"用便宜的 API 写吧"** — 但仍要 MiniMax 审一遍

### 路径 B 的 3 个前置条件 (如果真要用)

1. **头几章必须 MiniMax 写**: 让路径 B 有"风格锚定"可循. 即便 prompt 没说, 模型看一眼头几章原文就能学.
2. **喂入的不只是 codex, 还要包含头几章原文** (至少 200 字 × 3 章 = 600 字)
3. **跑完必须 MiniMax 后审** — 哪怕只改 30%, 不能直接 publish

## 路径 A 的具体操作模式 (本会话实践)

```python
# 1. 加载细纲 + codex + 已发布章节参考
import json
from pathlib import Path

coq = json.loads(Path('novelforge/books/qidian/codex.json').read_text())
recent_ch = Path('chapters/起点_第6章_江城第一餐.md').read_text()[-500:]

# 2. 对话窗口直接写章节
prompt = f"""
下一章目标: 起点 Ch7, 字数 3500-4500, 模仿 Ch1-6 风格.
Ch6 末尾 500 字参考:
{recent_ch}

codex 当前状态: {json.dumps(coq['current_state'], ensure_ascii=False)}

风格特征 (最重要):
- 标题格式: # 章节名
- 开头: 一句景物/场景 (例: "七月的江城, 热得像蒸笼...")
- 段落: 1-3 句/段, 大量句号, 少量感叹号
- 主线: 嘴贱/自嘲第一人称, 不装 X
- 接续: 从 Ch6 末尾自然往下, 不重置场景

细纲要求:
- 王大龙派人威胁母亲何秀兰+暖暖
- 主角派王小川+春风帮扶会志愿者去江北新区
- ...

现在直接写小说正文, 模仿 Ch1-3 风格. 不要前言.
"""

# 3. 在 write_file 工具里出文, 落到对应文件
# 4. 同步到 Desktop + Riky- 真源 + git push
```

## 路径A/B 同时在线时的踩坑 (本会话实踩)

### 坑: 路径B 把"已发布章节"当成普通文件

如果直接用 `python3 novelforge.py chapter <book> <num>` 走路径 B, 模型不知道自己**该模仿哪几章**. 必须手动喂入 Ch1-3 末尾.

### 坑: 路径A 写完没 sync 到 Riky-

write_file 写到 novelforge chapters/ 后, 还必须:
```bash
shutil.copy2(src, '/home/admin/Riky-/novels/起点_亏成首富从外卖开始/chapters/')
shutil.copy2(src, '/home/admin/Desktop/我的网文/起点_亏成首富从外卖开始/chapters/')
# 生成 .txt
# git push
```

详见 `novelforge-user-machine-bridge` 技能

## v0.5.3 修复后的双路径规则 (2026-07-04 终版)

**写章节正文 = 永远路径A** (本会话焊死)
**写其他 (audit / 调研 / 短摘要) = 路径B**

**不再做**: "头三章路径A / 后续路径B" 的二元区分 — 用户的反馈是 **"你AI根本写得不连贯"**, 这种风险远大于 token 成本.

**例外**: 用户明确指令"切到 aipro 写吧" (前提: 写完 MiniMax 必须审一遍)

## 风格锚定的 5 个具体特征 (写章节必须满足)

写之前先想: "我 (MiniMax) 写 Ch1-3 是怎么写的?"

1. **标题行**: `# 章节名` — 不能是"对话当首行"也不能是"你是XXX..."
2. **首段**: "七月的X" 景物 / "X走的那天夜里" 时间锚点 — 不允许 preamble / setup
3. **句长**: 平均 15-25 字, 极少 50+ 字长句
4. **段长**: 1-3 句/段, 段间空行
5. **人设**: 自嘲 / 嘴贱 / 平实 — 不装 X 不中二

如果路径B 章节不符合这 5 条 → 重新生成或改写.
