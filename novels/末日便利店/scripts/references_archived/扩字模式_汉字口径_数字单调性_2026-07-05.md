## 1. 字数统计口径(焊死, 必须用 Python 严格核对)

```python
import re
han = len(re.findall(r'[\u4e00-\u9fff]', text))
```

**为什么不用字符数**:
- markdown 字符 (`> ` `**` `#` 等) 占字符数但不算正文
- 一个 1900 字符的章节, **汉字可能只有 1200-1500**
- 用户原话 (2026-07-05): "刚才看到的是按字符数算的字数, 现在我换算成中文字符(\u4e00-\u9fff ASCII 外的汉字)重新数——有些'字数'其实之前算多了,因为包含了 markdown 字符"

**目标区间(2026-07-04 v0.5.2 用户钦定统一)**:
- **起点**: 3500-4500 字(汉字口径)
- **番茄**: 4000±10% 字(汉字口径, 2026-07-05 用户原话"字数还是4000左右就行")
- **未明确分类**: 按"是起点还是番茄"判定

**铁律**:
- ❌ 不用 `wc -m` / `wc -c`(包含 markdown 字符)
- ❌ 不用文件 size 估算
- ✅ 永远用 `re.findall(r'[\u4e00-\u9fff]', text)` 精确数

**字数与番茄签约生死线的区分(2026-07-05 焊死)**:
- 卷一细纲写"番茄 Ch4-Ch10 = 800-1000 字"是**签约生死线起点**(头3章 2000 字签约),不是单章上限
- 实际生产字数铁律 = 用户钦定的扩字铁律(4000±10% for 番茄)≠ 细纲的 800 字
- 当细纲字数与扩字铁律冲突 → **以扩字铁律为准**(细纲字数是签约线起步值,扩字铁律是量产字数)

## 2. 扩字任务 6 步标准流程

### Step 1: 抓现场
```bash
python3 -c "
import re, os
for f in sorted(chapters_list):
    text = open(f).read()
    han = len(re.findall(r'[\u4e00-\u9fff]', text))
    print(f'{os.path.basename(f):40s} 汉字={han:5d}')"
```
输出按缺口排序 (`target - current` desc), 缺口最大优先

### Step 2: 读上下文(必须)
扩字前必读:
- 当前章全文
- 前 1 章末 100 行(承接)
- 后 1 章首 100 行(钩子)
- **章末自检块**(确认作者备注的"下一章钩子"是哪一句)

### Step 3: 数字单调性检查(关键 BUG 防御)
**铁律**: 跨章"系统显示"数字必须**单调递增**(亏损/返利/累计), 不允许倒退。

**反例(2026-07-05 番茄 Ch8 真实踩雷)**:
```
Ch7 末: 累计亏损 5.5 万 / 累计返利 2750 万
Ch8 末: 累计亏损 4.2 万 / 累计返利 2100 万   ← 倒退!BUG!
```
读者一眼看穿=作者没记账=弃书。

**修复模式**:
```python
# 数字单调性校验
prev = read_chapter(n-1).end_state  # 累计亏损 / 累计返利
curr = read_chapter(n).end_state
assert curr.亏损 >= prev.亏损, f"Ch{n} 亏损 {curr.亏损} < Ch{n-1} {prev.亏损}"
assert curr.返利 >= prev.返利, f"Ch{n} 返利 {curr.返利} < Ch{n-1} {prev.返利}"
```

扩字时如果发现单调性破坏, **必须修复**, 不能只补字数。

### Step 4: 路径选择(2026-07-05 焊死)

| 条件 | 路径 | 模型 |
|---|---|---|
| 当前章是待审/草稿, 数字无 BUG, 单章扩 500-1500 字 | **路径 A** | MiniMax-M3 (对话窗口直写) |
| 当前章数字有大 BUG 需重算 + 重写 | **路径 A** | MiniMax-M3 |
| 批量 5+ 章待扩, 数字都自洽, 用户授权"用 1314 大模型" | **路径 B (1314)** | mc1314 deepseek-v4-flash |
| 🟢 已发布锁死章节, 不能扩 | — | 拒绝 |

**用户 2026-07-05 修正前 vs 修正后**:

| 项 | 旧 (web-novel-production v0.5.3) | 新 (2026-07-05) |

| 路径 B 用途 | audit / 调研 / struct data / 短摘要 | **可以用于扩字章节正文** (用户授权时) |

### Step 5: 扩字手法(段选模板)

按缺口大小选段(500 字以内选 1 段, 500-1000 选 2 段, 1000+ 选 3 段):

| 缺口 | 加段位置 | 内容模板 |

### 3.3 跨机器 git 同步模式 (2026-07-06 焊死)

**用户看的 .txt 不在 git 里** — 这是历史设计, 根 `.gitignore` 全局排除 `dist/`:

```gitignore
# Data — generated, not source
ds0_data.json
ds0_status.json
trade_count.json
*.json.gz
```

(注: 根 `.gitignore` 还包含 `dist/` 和 `build/` 排除 — 标准 Python 排除, dist 全局被排除)

**设计澄清**:
- `chapters/*.md` = **真源**, git 跟踪 (用户原话 "你之后就在仓库修改内容")
- `dist/*.txt` = **用户复制用版本**, **永远不进 git** (sed 转换 + 体积大)
- 任何 `git status` 看到 `dist/` 下的 deleted 状态 = 假象 (文件本来就没跟踪)
- 扩字/重写后必跑: `chapters/*.md` 真源 commit + `dist/*.txt` 重新 sed 生成到 Desktop

**同步命令 (扩字后必跑)**:
```bash
# 1. chapters/.md 同步到 Git 真源
cp Desktop仓库/chapters/xxx.md /home/admin/Riky-/novels/xxx/chapters/xxx.md
cd /home/admin/Riky- && git add novels/xxx/chapters/xxx.md && git commit -m "xxx"

# 2. dist/.txt 重新 sed 生成 (只到 Desktop, 不入 git)
sed -e 's/\*\*//g' -e 's/^# //' -e 's/^## //' -e 's/^---$//' \
    Desktop仓库/chapters/xxx.md > Desktop仓库/dist/xxx.txt

# 3. 推送
cd /home/admin/Riky- && git push origin main
```

**反例 (本会话差点踩)**:
- ❌ `git status` 看到 `D dist/xxx.txt` 就慌 → 实际是 dist/ 全局被排除, 删除状态是 git "untracked 消失"假象
- ❌ `os.remove` 一个未跟踪文件 → 让 git 误以为是"工作区删除"
- ✅ 正做: 看到 dist/ 下 `D` 状态 = 没事, 不需要处理; commit + push 只关注 chapters/*.md

## 4. patch 工具陷阱 (2026-07-05 实踩)

**问题**: `patch` 工具对同段落多次出现敏感, 报错 `Found N matches for old_string`

**触发场景**: 章节里多次出现通用短语("放心" / "他问" / "她说" / "嗯" / "得嘞"), 想用其中一处做锚点

**解决模式**:
```python
# ❌ 错: 用通用短语做锚点
old_string = "顾行舟笑了。"

# ✅ 对: 用更独特的上下文 + 行号锚点
old_string = "顾行舟笑了。\n\n'行舟,我跟你说实话。'\n\n'我这个便利店,不是普通便利店。'"

# ✅✅ 更好: 用 write_file 整章重写(缺口大时首选)
# 1. read_file 全文
# 2. write_file 新全文
# 避免 patch 多次失败浪费 token
```

**判定何时用 patch vs write_file**:
| 改动大小 | 工具 | 风险 |
|---|---|---|
| 1-2 段加在末尾 | `patch` | 低 (用章末自检块前的位置作锚点) |
| 改章首 | `patch` | 中 (可能命中多处) |
| 改章中通用短语 | `write_file` | 高 (必须用 write_file) |
| 改系统数字 | `patch` | 低 (数字唯一) |
| 整章扩 1000+ 字 | `write_file` | 首选 |

**反例(本会话踩)**:
- ❌ 第一次 patch 用 "顾行舟点头。\n\n'妈,您放心。'" 报 6 处匹配 → 浪费 1 轮
- ✅ 第二次 write_file 整章重写, 一次过

## 7. 🚨 扩字回检 SOP — 注水检测(2026-07-05 焊死 — 用户原话"番茄4-10章完全凑字数")

> **用户原话(2026-07-05)**: "重新看下番茄4-10章完全凑字数啊,重新修改下"

### 为什么扩字后必须回检

扩字时为凑目标字数,容易反复用同一种情绪过渡句兜底:
- "他看着..." / "他望着..." / "他盯着..."
- "沉默" / "没说话"
- "他心想..." / "他心里想..."
- "他愣了一下" / "他顿了顿"
- 同样的对话轮次(同一人反复说意思相同的话)

**字数达标 ≠ 质量达标**。汉字口径数对了,但全是情绪词堆砌 = 用户看 2 页就识破"注水"。

### 7.1 注水密度阈值(2026-07-05 实测焊死)

| 信号词组 | 单章阈值(汉字4000字) | 单章阈值(汉字1800字) | 判定 |
|---|---|---|---|
| 看着 + 望着 + 盯着 | ≤ 8 次 | ≤ 4 次 | 超 = 🟡 注水嫌疑 |
| 心想 + 心里想 + 想道 | ≤ 4 次 | ≤ 2 次 | 超 = 🔴 严重注水 |
| 沉默 + 沉默片刻 + 没说话 | ≤ 5 次 | ≤ 3 次 | 超 = 🟡 注水嫌疑 |
| 愣了一下 + 顿了顿 + 怔了怔 | ≤ 6 次 | ≤ 3 次 | 超 = 🟡 注水嫌疑 |
| 主角名(`行舟`/`北舟`/`林北`) | ≤ 80 次 | ≤ 40 次 | 超 = 🔴 主角中心过度 |
| 对话回合数(`「"/"` 计数) | ≥ 200 | ≥ 100 | 少 = 🟡 缺乏对话推进 |

### 7.2 自动检测脚本(扩字完必跑)

```python
import re

def check_padding(chapter_text: str, target_chars: int = 4000) -> dict:
    """注水密度检测 — 扩字后必跑"""
    cn = re.findall(r'[\u4e00-\u9fff]', chapter_text)
    total_han = len(cn)
    scale = total_han / target_chars  # 章节字数缩放因子

    signals = {
        '看着/望着/盯着': len(re.findall(r'(看着|望着|盯着)', chapter_text)),
        '心想/心里想/想道': len(re.findall(r'(心想|心里想|想道)', chapter_text)),
        '沉默': len(re.findall(r'(沉默|没说话|沉默片刻)', chapter_text)),
        '愣/顿': len(re.findall(r'(愣了一下|顿了顿|怔了怔|怔了一下)', chapter_text)),
        '主角名': len(re.findall(r'(行舟|北舟|林北)', chapter_text)),
        '对话回合': len(re.findall(r'[「"]', chapter_text)),
    }
    thresholds_4000 = {  # 4000字阈值
        '看着/望着/盯着': 8, '心想/心里想/想道': 4, '沉默': 5,
        '愣/顿': 6, '主角名': 80, '对话回合_min': 200,
    }
    issues = []
    if signals['看着/望着/盯着'] > thresholds_4000['看着/望着/盯着'] * scale:
        issues.append(f"🔴 看着/望着/盯着过多: {signals['看着/望着/盯着']} 次 (阈值 {int(thresholds_4000['看着/望着/盯着']*scale)})")
    if signals['心想/心里想/想道'] > thresholds_4000['心想/心里想/想道'] * scale:
        issues.append(f"🔴 心想过多: {signals['心想/心里想/想道']} 次")
    if signals['沉默'] > thresholds_4000['沉默'] * scale:
        issues.append(f"🟡 沉默过多: {signals['沉默']} 次")
    if signals['主角名'] > thresholds_4000['主角名'] * scale:
        issues.append(f"🔴 主角名出现 {signals['主角名']} 次,偏主角中心")
    if signals['对话回合'] < thresholds_4000['对话回合_min'] * scale:
        issues.append(f"🟡 对话过少: {signals['对话回合']} 回合 (下限 {int(thresholds_4000['对话回合_min']*scale)})")

    return {
        'pass': len(issues) == 0,
        'signals': signals,
        'issues': issues,
        'total_han': total_han,
    }

# 用法 — 扩字后必跑
result = check_padding(open(chapter_path).read(), target_chars=4000)
if not result['pass']:
    print("❌ 注水检测未通过:")
    for issue in result['issues']:
        print(f"  {issue}")
    print("\n→ 必修后再交付 (不是返工, 是重写)")
```

## 8. 🚨 对话式剧情注水检测(2026-07-05 焊死 — 用户原话"番茄4-10章完全凑字数,改下逻辑")

### 8.1 根因诊断(2026-07-05 实测)

每章扩字时,我用"7步思维链"逐动作展开,导致对话回合数爆炸:

```
7步思维链(❌ 错误模式):
1. 什么场景   → 主角观察环境
2. 主角怎么想 → 心里盘算
3. 主角怎么说 → 一句对话
4. 对方怎么回 → 一句回应
5. 主角怎么想 → 再心里盘算
```

**正确写作逻辑(✅ 路径A 写作逻辑)**:

```
1. 场景锚点(2-3句景物/时间/地点)
2. 1段动作(主角做了什么)
3. 1-2句对话(推进剧情用,不重复信息)
4. 1段结果(动作的结果/环境变化)
```

- 信号词 (看着/心想/沉默): 见 7.1 表

### 8.2 对话密度阈值(2026-07-05 实测焊死)

| 信号 | 4000字章阈值 | 判定 |
|---|---|---|
| 对话占比 (`对话字数/总汉字`) | ≤ 50% | 超 = 🔴 对话注水 |
| 对话回合数 (`「` + `"` 计数) | 30-50 回合 | 超 60 回合 = 🔴 |

### 8.3 对话注水检测脚本

```python
import re

def check_dialogue_bloat(chapter_text: str, target_chars: int = 4000) -> dict:
    """对话式剧情注水检测 — 扩字/重写后必跑"""
    cn_chars = len(re.findall(r'[\u4e00-\u9fff]', chapter_text))
    scale = cn_chars / target_chars

    # 对话段: 中英文引号包裹 (可能含换行)
    dialogues = re.findall(r'[「"][^「"\n]{1,500}[」"]', chapter_text)
    dialogue_chars = sum(len(re.sub(r'[\s「」"]', '', d)) for d in dialogues)
    dialogue_pct = dialogue_chars * 100 / max(cn_chars, 1)
    dialogue_turns = len(dialogues)
    dialogue_density = dialogue_turns / max(cn_chars / 1000, 1)

    issues = []
    if dialogue_pct > 50 * scale:
        issues.append(f"🔴 对话占比 {dialogue_pct:.1f}% > 50% (阈值 {50*scale:.0f}%)")
    if dialogue_turns > 60 * scale:
        issues.append(f"🔴 对话回合 {dialogue_turns} 回合 > 60 (阈值 {60*scale:.0f}回合)")
    if dialogue_density > 15:
        issues.append(f"🔴 对话密度 {dialogue_density:.1f} 回合/千字 > 15")

    return {
        'pass': len(issues) == 0,
        'cn_chars': cn_chars,
        'dialogue_pct': dialogue_pct,
        'dialogue_turns': dialogue_turns,
        'dialogue_density': dialogue_density,
        'issues': issues,
    }

# 用法 — 改写后必跑
result = check_dialogue_bloat(open(chapter_path).read(), target_chars=4000)
if not result['pass']:
    print("❌ 对话注水检测未通过:")
    for issue in result['issues']:
        print(f"  {issue}")
    print("→ 必修对话密度,不是简单删字数")
```

### 8.5 修复模式 — 对话改叙事

| 对话模式(❌ 凑字数) | 叙事模式(✅ 推进剧情) |
|---|---|
| "你干啥?"<br>"我看看。"<br>"看啥?"<br>"看这个。"<br>"这是啥?"<br>"这是个事。" | 顾行舟盯着手里的东西看了三秒,转身走进了隔壁房间。<br>(场景:主角做了什么) |
| 一方反复追问"为什么为什么为什么"<br>另一方反复回应"因为因为因为" | 主角听到这个回答,愣在原地,盯着墙上的旧照片看了很久。<br>(场景:用动作表达情绪,不靠对话) |
| 双方你一言我一语来回 5 轮 | 用一段叙述交代背景 + 一句关键对话定锚 + 一个动作收尾 |

**核心原则**:
- **对话是工具,不是内容**: 1-2 句关键对话定锚,其余用叙述推进
- **情绪靠动作,不是嘴炮**: 主角"愣住了"不如"主角把手里的茶杯放下了"
- **信息靠场景,不是问答**: "你叫啥?" "我叫顾行舟" → 不需要,直接"顾行舟走进便利店,老板抬头看了他一眼"
- **场景描写必须有信息**: 不是为美而美,是为主角下一步行动铺垫

### 8.6 字数与对话密度平衡公式

```
目标字数 = 4000 字
对话占比 ≤ 50% = ≤ 2000 字是对话
非对话字数 ≥ 2000 字 = 场景 + 动作 + 心理 + 景物

场景/动作段落: 1 段 100-300 字 = 1 个推进
对话段落: 1 段 50-150 字 = 1 个信息
心理/情绪: 1 段 50-200 字 = 1 个情感点

4000 字 = 8-10 个场景段 + 5-8 个对话段 + 3-5 个心理段
```

- Ch10 实际: 471 个对话段 + 极少动作段 = 角色嘴炮 30 分钟,场景零推进
