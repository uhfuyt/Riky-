# AI质量双门 — 每章产出后必跑

> **触发**: 用户原话"加一个合理化或者去 AI 味的功能 每次写完之后检查一下,是不是跟真人写的一样"
> **位置**: `novelforge/ai_detector.py` + `novelforge/plausibility.py` + `novelforge/ai_rewriter.py`
> **集成位置**: `novelforge/consistency.py` 的 `audit_chapter()` 已自动调用

## 🚦 三道闸门(按顺序跑)

### 第一道: AI味检测 (ai_detector.py)

**7个维度,目标 ≥ 75**:

| 维度 | 检查内容 | 检测算法 | 真人特征 vs AI特征 |
|---|---|---|---|
| 段落结构 | 长短不齐 | 段落长度变异系数 (CV) | 真人CV>0.5 / AI CV<0.3 |
| 对话节奏 | 短句+语气词 | 平均句长 + 语气词密度 | 真人短句多 + 啊/嗯/唉 |
| 情绪标点 | !连用和…… | !密度 + ……密度 | 真人!密度>0.3 / ……>0.2 |
| 词汇重复 | 口头禅 | 2-4字词频 | 真人15-30%重复 / AI 5-15% |
| 环境描写 | 形容词堆砌 | 形容词密度 (的/地/得) | 真人2-5个/百字 / AI 6-12个 |
| 剧情节奏 | 时间跳跃 | 场景切换标记 + 时间跳 | 真人跳跃多 / AI顺滑 |
| 金句段子 | 自我吐槽 | 调侃词密度 (我操/靠/?) | 真人>1.0/百字 / AI<0.1 |

**总分加权**: 段落20% + 对话20% + 标点15% + 重复10% + 环境10% + 节奏15% + 段子10%

**评级**:
- ≥90: 🟢 真人级
- 75-90: 🟡 不像AI
- 60-75: 🟠 略有AI味(可读)
- <60: 🔴 AI味重(必须改)

### 第二道: 合理化检测 (plausibility.py)

**7个维度,目标 ≥ 75**:

| 维度 | 检查内容 | 检测算法 | 常见bug |
|---|---|---|---|
| **数学一致性** | 返利 = 亏损 × 倍数 | 正则提取"亏X→返Y" | 19.6万×1万=196亿,不是19.6亿 |
| **数值膨胀** | 相邻章资产跨度 | 当前/历史现金 | Ch1破亿Ch2破万亿=读者不信 |
| **升级曲线** | 等级是否过快 | 累计亏损/升级阈值 | Ch3不应Lv.10 |
| **时间逻辑** | 一天事件密度 | 时间标记去重 | 一天5+时段=剧情太赶 |
| **因果链** | 反派动作→应对 | 反派词/主角词比 | 反派8次动作主角0应对=弱 |
| **规则一致** | 触碰禁区 | ban_list关键词 | 主角去赌博=违规下架 |
| **人设一致** | 行为匹配性格 | voice_quotes | 主角心软但全章冷漠=人设崩 |
| **开篇格式**(2026-07-03 新增) | 禁日期开头/作者注/数据卡/方括号剧透 | 8条规则正则匹配 | 触发任一 → -25分,触发任二+ → FAIL(必须删干净重写) |

**开篇格式铁律完整版**: 详见 `references/章节开头7禁_2026-07-03.md`(含 8 条正则 pattern + 锁死判断 + 真实正确例子)。
**accept 铁律**(本会话加,2026-07-03): 不要只看 `total`,要看每一维度分数 —— 任一维度低于阈值就拒收。详见 `references/总分陷阱_别只看total_2026-07-03.md`。

**评级**:
- ≥90: 🟢 合理
- 75-90: 🟡 略有不合理
- 60-75: 🟠 需修
- <60: 🔴 崩了

### 第三道(可选): AI味改写 (ai_rewriter.py)

`rewrite(text, level='medium')` 按分数自动改:
- `paragraph < 70` → 长段切短(1-2行短段)
- `dialogue < 70` → 主角话砍短 + 加语气词
- `punctuation < 70` → 加!和……
- `repetition < 60` → 加4次主角口头禅
- `environment < 60` → 砍"金碧辉煌"等堆砌
- `pacing < 65` → 加"第二天"等时间跳
- `humor < 60` → 加"——心里已经在骂街了"

**已知局限**: 改写器实际改了内容,但检测器对短章反应迟钝,**改写前后分数几乎不变,人读得出差别**。100+章样本重训可改善。**详情见本文末尾"检测器vs改写器失同步"小节**。

## 🚨 用户真正在意的崩塌:剧情 pacing 锁(2026-07-03 焊死)

**用户原话**: "番茄是不是太夸张,返这么多,剧情设定会崩的啊"

**核心认知(重新校准)**: 用户对网文质量的 **第一优先级不是 AI味**,**是剧情合理性/数字可信度**。AI 味可以"凑合看",**数字通胀读者立刻弃书**。

### 三层 pacing 锁(从源头锁死,不是检测器补救)

1. **A. 分级返利曲线** (详见 `novelforge-architecture` → 💎 金手指反套路模式)
   - **禁止** "固定10000x一路到底" — Ch1破亿,Ch5破100万亿,读者翻白眼
   - **强制** Lv.1=10000x → Lv.5=1000000x,曲线增长,给"升级感"

2. **B. 日限额机制** — 强制产生"每天想新办法亏钱"的剧情动力
   - 没日限 → 主角Ch1花19.6万返196亿 → 第二天再花1960万返1.96万亿 → **5章崩盘**
   - 有日限 → Ch1当天只返1亿 → 后面19天每天9000万 → **剧情可写1个月**

3. **C. 章末数字 + 章内数字双控** — **2026-07-03 新增**
   - 章内数字: 单章出现的最大数字 ≤ 当前等级理论返利的 1.5 倍
   - 章末数字: 单章结束后主角资产 ≤ 上一章结束 × 10 倍
   - 触发条件: 数字跨度过大 → **先拆分章节或加过渡段**,不要在 1 章内塞 5 个数字大跳跃

### 番茄 Ch1 实战教训(A+B 之前 vs A+B 之后)

| 维度 | A+B 之前(崩) | A+B 之后(过) |
|---|---|---|
| 单章数字 | 19.6万 → 19.6亿 | 19.6万 → 196亿 + 日限1亿 + 195亿待补 |
| 数学正确性 | ❌ 19.6亿 = 19.6万 × 10000/10,少10倍 | ✅ 196亿 = 19.6万 × 10000 |
| 数字可信度 | Ch2必然1000亿+,Ch5必然破百万亿 | Ch30-Lv.3 50000x + 日限100亿 = 5000亿/天,**可持续** |
| 用户评价 | "剧情容易崩啊" | ✅ 数学 86.8, AI 82.0 双合格 |

## 📅 Day-N 时间线法(2026-07-03 新增 — 解决时间过密)

**坑**: 起点 Ch6 原版"7月8日"一整天塞了 5 个大事件(转50万 + Lv.3升级1亿 + 暖暖来 + 母亲来 + 律师 + 苏婉清起诉),**plausibility.time_logic_score=68.2,被标"时间过密"**。

**修复**: 卷一细纲里加 **Day-N 时间线表**,每章标注"第N天(7月X日)",每章**只写一天**,事件数 ≤ 3。

### Day-N 时间线表模板(写到细纲开头)

```markdown
## 🔑 关键:全卷时间线(每章标注"第N天"防时间过密)

| 章 | 日期(7月) | 标题 | 主角等级 | 现金 |
|---|---|---|---|---|
| Ch1 | 7月2日 下午 | 系统激活 | Lv.1 (10x) | 4,356元 |
| Ch2 | 7月2-3日 | 第二个亏单 | Lv.1 | 51万 |
| Ch3 | 7月4日 早 | 王大龙登场 | Lv.2 (20x) | 51.8万 |
| **Ch4** | **7月5日 早** | **母亲来电** | Lv.2 | 51.8万 |
| **Ch5** | **7月5日 上午** | **第一次被问话** | Lv.2 | 51.8万 |
| **Ch6** | **7月8日 上午** | **升级Lv.3 1个亿** | Lv.3 (50x) | 1亿+ |
| **Ch7** | **7月9日 中午** | **暖暖+母亲来江城** | Lv.3 | 1亿+ |
```

**铁律**:
- 单章内**最多跨一天**(如 Ch2 = "7月2日晚 - 7月3日",但不能跨3天)
- 单章内事件 ≤ 3 个(系统升级 + 大额转账 + 一个情绪高点 = 满载)
- 跨章时主角**不能有时空跳跃**(Ch5在江城派出所,Ch6不能突然在香港)

### 章节拆分模式(密度超限 → 拆)

**症状**: 一章里检测器 time_logic_score < 70,说明一天里塞了 5+ 时段事件。

**修复**: **不要硬塞,直接拆**。

**案例**: 起点 Ch6 拆成 Ch6 + Ch7
- 原 Ch6: 7月8日 上午(50万任务 + Lv.3升级 1亿) + 下午(王大龙500万到账 + 苏婉清起诉 + 暖暖来 + 母亲来 + 律师)
- 拆 Ch6: 仅 7月8日 上午(50万任务 + Lv.3升级) → 3500字
- 拆 Ch7: 仅 7月9日 中午(暖暖来 + 母亲来 + 蛋炒饭 + 苏婉清起诉) → 3500字

**检测**: 拆分后 Ch6 时间逻辑分从 68 → 80, Ch7 = 83, 双合格。

## ⚠️ 检测器vs改写器失同步(2026-07-03 实战教训)

**坑**: 跑 `ai_rewriter.py chapters/起点_第4章_母亲来电.md medium` 后,代码**确实改了文本**(加了口头禅"我林北舟,穷得只剩运气了"等),但 `ai_detector.detect()` 跑出来的分数**几乎不变**(改前 70.5 → 改后 70.5)。

**根因**: 检测器的 7 个维度算法对短章(3000字内)反应迟钝 — 段落变异系数、词汇重复率等指标在 2000-3500 字这个范围内变化太小,加几个口头禅/感叹号分母变化不到 1%。

**实战意义**:
- **改写器输出永远值得人读对比**(`_重写.md` 文件),即使分数不变
- **分数是参考,不是真理**
- 真正校验靠 **人读 + 番茄/起点作者助手编辑反馈**
- **改进方向**: 检测器需要 100+ 章"真人对 AI"标注样本重训(目前 0 章样本)

**给 DS-0 的操作规则**: 改写器输出后,**先 diff 对比**:
```bash
diff chapters/起点_第N章_xxx.md chapters/起点_第N章_xxx_重写.md | head -50
# 看实际改了哪里,人读判断是否保留
```
然后再决定用哪个版本入库。**不要只看分数**。

## 🔧 plausibility.py 已知Bug修复(2026-07-03)

### Bug 1: 正则不捕获单位
- **症状**: "1万"被解析为1
- **原因**: 原正则 `(\d+)` 后接 `[万亿千百元块]?` 是可选的,非贪婪匹配
- **修复**: `(\d+\s*[万亿千百元块]?)` 强制捕获单位
- **位置**: `_check_math()` 第44行

### Bug 2: 规则检测误判对话
- **症状**: "黄了"/"被骗"/"我没洗钱"被算作违规
- **原因**: 简单字符串包含
- **修复**: 只检测"主角靠xx赚钱"模式
- **位置**: `_check_rule_violation()` 第177行

### Bug 3: 数学检测漏日限
- **症状**: 番茄Ch1"19.6万→19.6亿"数学错却没扣分
- **原因**: 检测器认不出"待补/分期"等关键词
- **修复**: 检测到"待补/分期/日限/明日/次日"任一关键词,允许超额
- **位置**: `_check_math()` 第60行

### Bug 4: 数学检测误判惩罚
- **症状**: "扣除返利5倍"被算作返利而非惩罚
- **修复**: 检测"扣除/扣回/扣返"等关键词,跳过
- **位置**: `_check_math()` 第65行

### Bug 5: 因果链跨章失效(2026-07-03 新发现)
- **症状**: 起点 Ch3 合理化分 64.5,plausibility 报警"因果链弱:反派出招但主角应对不足"
- **根因**: 检测器**只看单章内**反派动作和主角应对。反派的8次动作 + 主角0次应对 → 0.00 比 → 扣分
- **实际原因**: 那些反派动作在 Ch3 是"陈述过去事实"(Ch1-Ch2 已发生),主角应对在 Ch4-Ch5,**检测器看不到跨章因果链**
- **缓解**: 
  - 不要因为单章因果链扣分就重写 Ch3 文本(Ch3 文本是对的)
  - 改成"每卷做一次跨章因果审计"(卷末检查所有反派动作是否都有主角应对)
  - 单章因果链分 < 50 才标记为真bug
- **位置**: `_check_causality()` 第120行

### Bug 6: 数学检测误判"惩罚"为"返利"
- **症状**: Ch3"扣除返利5倍"被算作返利数字,触发返利倍数检查
- **修复**: 检测"扣除/扣回/扣返"等关键词,跳过

## 🚀 标准流程(每章产出后)

```bash
# 1. 跑 audit (一次性跑3个维度)
python3 novelforge.py audit {book} chapters/起点_第N章_xxx.md
# 检查输出:
#   - ai_score >= 75
#   - plausibility_score >= 75
#   - 没有 FAIL 项
# 注意: 因果链 < 50 才是真bug,60-70 是跨章误判,可忽略

# 2. 如果 AI 味 < 60: 跑改写器
python3 ai_rewriter.py chapters/起点_第N章_xxx.md medium
# 输出 _重写.md
diff chapters/起点_第N章_xxx.md chapters/起点_第N章_xxx_重写.md | head -50
# 人读判断保留哪个

# 3. 如果 合理化 < 60 且不是因果链: 必须手动重写
#    改写器不改剧情bug,只看人读,改完再 audit

# 4. 都通过后: 转 .txt + Telegram + git
```

## 🎯 给DS-0的自检问题(每章产出前)

写完后过一遍这7个问题,**任何一个答不出来就重写**:
1. 这章主角"花"的钱数 × 倍数 = 返利数,数学对吗?
2. 今天到账的钱 ≤ 日限额吗?
3. 等级符合累计亏损阈值吗?
4. **这一天有几个时段? ≤ 4 个吗?**(新增重点)
5. **单章最大数字跳变 ≤ 10 倍吗?**(新增重点)
6. 反派出招主角都有应对吗?(单章内,跨章不算)
7. 主角说的话符合他性格吗?

## 🚀 验收铁律(2026-07-03 总结)

**每章必跑** `audit`,不通过不发 Telegram:
- AI味 < 60: 用 `ai_rewriter.py` 自动改,再 audit
- 合理化 < 60: **必须手动重写关键段**(改写器只改AI味,不改剧情bug)
- 数学检测到错误(如19.6亿vs196亿): 重写整章数字

**改写后必须 diff 对比**,分数不是真理。

**番茄 pacing 问题 = 用户头号否决理由**,不是 AI味。**数字可信度 > AI 拟人度**。
