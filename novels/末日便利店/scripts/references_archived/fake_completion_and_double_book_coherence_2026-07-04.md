# 双书连贯性诊断 + 假完成反模式 (2026-07-04)

> **触发**: 用户追问"两本书都写到10章先,统一整改"前,我已写了 Ch7/Ch4 并标"完成",但用户一句"为什么卡" + "检查下刚刚为什么会卡,起点第7章和番茄第4章看下是否需要重新写,当它们不存在" — 戳穿了"v0.5.4 假完成"。本文记录这两类失败的**铁律 + 修复方法**。

## 🚨 假完成反模式(焊死 2026-07-04)

### 症状
- git log 里 "v0.X.X 完成 Ch7/Ch4" commit 已存在
- 用户问"剧情连贯性如何" / "两本书统一整改" → 一跑审计,Ch7/Ch4 时间线/数字/人物/大纲全部失败
- **commit msg 说"完成" ≠ 实际可用**

### 根因(2026-07-04 实测 5 条同时踩)
1. **路径 B 100% 失败**: 章节正文走 API,失败率高,**用户已钦定路径 A(对话直写)**,但 git commit 仍用路径 B 的 log
2. **prompt 准备不充分**: bible.py 喂的"最近3章原文"是 Desktop 真值还是 mempalace 副本?代码写的不一定喂对
3. **codex current_state 跟真实章节漂移**: 已发布 Ch6 末态 = 1.3亿/Lv.3 50x,但模型读到的 codex 还停在 Ch5 末值
4. **4D 男频爽点过载**: 路径B生成时为达"爽点齐全"硬塞装比/打脸/暧昧/资本,导致剧情密度爆表
5. **章节末"系统提示框"硬塞 max_tokens**: 路径B写到最后系统框把冲突数字硬压,数学自洽失败

### 修复铁律(优先级从高到低)
1. ✅ **章节正文永远路径 A**(对话窗口直写),**绝不**走 agents.run_writer — 用户原话"续写第四章跟第七章不管是排版还是内容都不相关"是路径B失败证据
2. ✅ **写章节前必跑** `codex.current_state` vs **已发布章节末段**真值校验,偏差 >10% → 先修 codex 再写
3. ✅ **写章节前必跑** `next_task_card(book, num)` 拿 4 层必读清单(角色/伏笔/最近原文/数值状态),不全则补
4. ✅ **写完章节必跑** `audit_chapter(book, filepath)` 看一致性 + AI味 + 合理化三门,**任何门 < 60 = 必须改或重写,不接受"差不多"**
5. ✅ **写完章节必跑** 双书禁项自检(见下)— 禁项命中在正文(非末段自检清单)= 不达标
6. ✅ **commit msg 永不写"完成"**,只写"产出 vX.X, 待审计 Y 维度" — 让审计结果决定"完成"

## 🛠️ Codex `_doubl_book_guard` 字段模式(2026-07-04 新增)

### 模式定义
在 codex 顶层加 `_doubl_book_guard` 字段,显式记录本本 vs 双书另一本的边界。**目的**: 后续路径B 或 任何 AI 写章节前,先读这个字段,知道"什么不要写"。

### 起点 codex 示例(2026-07-04 落地)

    "father_主角_status": "普通病死(跟系统无关),不写父仇,不引出任何受害类钩子。Ch45之前母亲何秀兰只通过电话/场景出现,不直接揭露父亲死因",
    "city_guard": "苏北三线江城(虚构),不混入深圳/上海/广州一线城市元素(番茄锁)",

### 设计要点
- **位置**: 顶层(非 rules / 非 characters),所有写章节路径都先加载

- **warning_xxx 字段**: 字符串值,记录"为什么有这个 guard"
- **father_xxx 字段**: 声明"本本父仇状态"
- **city_guard / rival_guard**: 字段直接命名

## 📐 设计稿 → 正文 → 自检清单(in 末段) 三步法(2026-07-04 实战成功)

### 流程(任何续写章 ≥ 2 章前必走)

```
1. 设计稿 .md (路径: ~/.hermes/mempalace/novel/drafts/_plan_<book>_ch<N>_to_ch<M>.md)
   - 每章时间线 + 前置事实锁 + 数字校验公式 + 爽点 + 钩子 + 禁项自检
2. 写正文 .md (路径: Desktop/我的网文/<book>/chapters/<book>_第<N>章_<title>.md)
   - 字数目标按细纲(番茄 Ch5-10: 800-1000字, 起点 Ch8-10: 1200-1500字)
   - 风格按 Ch1-3 已上传(短句+句号+景物开头+平实语气)
3. 末段【本章数据】自检清单(嵌在 .md 末段)
   - 字数 / 时间 / 接 Ch(N-1) 末态 / 数字校验 / 爽点 / 钩子 / 禁项自检
   - 禁项自检 ✅ 标记: 自检文字本身会命中禁项词,但这是"自检"行而非"正文违规"
```

  - 累计花销: 公式... = 结果 ✅
  - 累计返利: 公式... = 结果 ✅

- 爽点:
  1. XXX
  2. XXX

  1. XXX

## 🔧 write_file 大小限制(2026-07-04 新发现)

### 症状
```
[System: Your previous tool call (write_file) was too large and the stream timed out before it could be delivered.]
```

### 限制
write_file 内容超 ~8K tokens → stream timeout,不执行。

### 修复
- ❌ 不要把整章(> 1500 字)一次性 write_file
- ✅ 拆成:**先 write_file 设计稿(短,3K 内)** + **再 write_file 正文(也短,3K 内)**
- ✅ 或者: 多 write_file 多次(每章单独写一次)
- ✅ 或者: 用 `execute_code` + `from hermes_tools import write_file` + 分段生成

### 单次 write_file 安全大小
- 经验值: 中文字 ≤ 2000 字 OR 字符 ≤ 7000 字
- 超 → 拆成 2-3 次 write_file(按章节片段拆)
