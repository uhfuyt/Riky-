## 何时该停止调研而直接用内部资源?

**自检清单**(任何"学习/调研"任务必跑):

- [ ] 已尝试 ≥2 个独立外部渠道且全部失败?
- [ ] 内部已有相关 skill / reference / template 文件?
- [ ] 用户授权我可以"凭内部资源决策"?

**3 个全 Yes** → 立即停止调研,告诉用户"外部 API 死,改用内部 X reference",然后基于内部资源出方案。

**1 个 No** → 继续尝试其他渠道(见下方"破局方法表")。

## 当外部 API 部分死时的破局方法表

| 死法 | 破局 |
|---|---|
| `web_search` 404 | 试 `delegate_task` with `toolsets=["web","skills"]` (可能命中 surf skill) |
| `delegate_task` 全失败 | 试 `curl` 起点/番茄 M 站 + 完整 UA + Referer(可能绕过 WAF) |
| `curl` 全部 209字节 | 试浏览器:`browser_navigate` 加载 → `browser_snapshot` 取文本 |
| `browser_navigate` -11 | chromium 崩,等几分钟重试;如持续崩,**直接放弃外部调研** |
| `cpapi` 需签名 | 找 `majax`/`ajax` 公开 API(例如 `/majax/rank/yuepiao` 这种), 仍失败就放弃 |
| 中文搜索全失败 | 试 Bing 英文 + 关键词中文(`qidian`+`yuepiao ranking` 之类) |

**破局 5 次仍失败** → **必须停止**,告诉用户用内部资源代替。
