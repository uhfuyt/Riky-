# 网文榜单抓取失败处理范式 (2026-07-04 焊死)

> ⚠️ **本references记录一个重要的"环境约束 vs 任务可行性"权衡**,是这次全分类学习方案的核心教训。

## 一、本次问题复盘

### 目标
为 5 个分类(玄幻/历史/军事/科幻/无限流)各产出一份「Top-20 头部作品」实测数据,作为后续手册的"卖点评测"基础数据。

### 失败现场(零隐瞒)
1. **起点中文网反爬死防**:`curl -s https://www.qidian.com/rank/xuanhuan/` 返回 209 byte 空壳页,标题为 "error--起点中文网"
2. **Jina Reader 兜底失败**: `curl -s https://r.jina.ai/https://www.qidian.com/rank/xuanhuan/` 拿到内容,但内容是**空壳 + 错误提示**
3. **Playwright (with python) 也失败**: 强制指定 chromium-1217 后,虽然能加载页面,但**拿到的是同样空壳内容**
4. **DuckDuckGo HTML 模式也失败**: 拿到的是 `anomaly.js` 反爬验证页
5. **龙空论坛失败**: 拿到首页但**玄幻板块是 3783 字节空白页**(可能需要登录/IP验证)
6. **第三方小说站(qd5200/biquge/ranwen)失败**: 服务器连接失败 / 重定向到主页
7. **子Agent delegation 也失败**: 子Agent的 API 返回 HTTP 404,直接标"completed"无任何实际抓取

### 根因诊断
**服务器 IP (100.90.63.122) 被这些网站大部分黑名单/屏蔽**,这是新加坡机房的IP段特性——很多国内大站对境外IP重封严。

## 二、按用户铁律的正确处理(已采用)

### 用户原话焊死(2026-07-04)
> "对数据造假零容忍。永远不要编造回测/策略/进度数据。不跑就说跑不动,跑多久说多久。"

**这次没踩雷的关键**:
1. **我用了 10 分钟真的去试**(curl / playwright / Jina / DDG / 龙空 / 子Agent delegation)
2. **如实在 SKILL.md/手册开头标注免责声明**: "基于行业知识模型 + 经典头部作品经验,**未含2026年7月实时榜数据**"
3. **不编榜数据**,只**用模型已有知识产出可用的金手指公式/红线/口头禅**
4. **告诉用户:** "服务器IP被反爬屏蔽了,你看到头部后告诉我,我 patch 手册"

### 这是"零造假"的正确解读
- ❌ 错: 没数据就**编造"假榜数据"** — 踩雷
- ❌ 错: 没数据就**停手等用户** — 浪费工具能力
- ✅ 对: 没数据就用**别的可信源**(本行业知识模型/经典作品),**标注数据来源**,**留接口让用户patch**

## 三、未来抓榜单的处理 SOP(给自己)

### 检查清单(每次抓榜单前必跑)

```
1. [ ] curl 测试目标URL,看返回内容/字节数
2. [ ] Jina reader 兜底: curl -s https://r.jina.ai/URL
3. [ ] Playwright 强制指定本地 chromium-1217 executable_path 试探
4. [ ] DuckDuckGo HTML / Bing 兜底搜索头部
5. [ ] 龙空/百度贴吧/微信公众号等中文社区搜索

如果全部失败:
6. [ ] 检查 server IP 段是否被 ban: curl ifconfig.me
7. [ ] 确认代理(用户配的)是否可用
8. [ ] **不要编数据**,改用模型知识 + 标注免责声明
9. [ ] 在产出文档里明示 "本内容基于训练知识,不是实时榜" 并提供手动 patch 入口
```

### 备用数据源(优先级)
1. ✅ **模型自身知识**(免费+可靠) — 经典作品、公式、红线
2. ✅ **用户手动喂入** — 用户看到头部后告诉我
3. ⚠️ Jina Reader(部分可用,反爬严的抓不到)
4. ⚠️ Playwright 本地 chromium(部分可用,需要 exponential retry)
5. ❌ 起点/番茄/百度(服务器IP被反爬)

### Playwright 反爬应对
```python
async with async_playwright() as p:
    browser = await p.chromium.launch(
        headless=True,
        executable_path='/home/admin/.cache/ms-playwright/chromium-1217/chrome-linux64/chrome',  # 不要用 1223
        args=[
            '--no-sandbox',
            '--disable-blink-features=AutomationControlled',
            '--disable-web-security',
            '--user-agent=Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0 Safari/537.36'
        ]
    )
```

### 子Agent delegation 在榜单抓取上不可靠
**教训(2026-07-04 焊死)**:
- ❌ 子Agent返回 `status=completed` **但**子Agent内容是 "API call failed after 3 retries: HTTP 404"
- ❌ 我(主Agent)如果不读错误信息,**以为数据回来了,直接采用 = 严重踩雷**
- ✅ 必须**逐字读完子Agent的完整结果**,看到"failed / 404 / error"等关键词**必须判定为失败**,重新手动跑或转方案

## 四、数据来源标签规范

**任何产出引用"网络实时数据"的文档,必须在开头明示数据来源**:
```markdown
> ⚠️ 数据来源: [实时榜 / 模型知识 / 用户喂入 / 既有档案]
> 更新时间: YYYY-MM-DD
> 抓取环境: [成功 / 失败(原因)]
> 如更新数据请联系: [途径]
```

**这是用户"零容忍"铁律的反向工程** —— 给数据来源标签 = **审计友好**,用户/同事随时验真。
