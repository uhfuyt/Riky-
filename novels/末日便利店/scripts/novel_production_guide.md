## 二、字数标准（当前活跃档位）

- **3000字上下** = ±20% 灵活区间 = **2400-3600汉字**
- "左右/上下" = ±20%，"以内" = 硬上限 ≤X

## 四、铁律清单

### 铁律1️⃣ 对话回声病
- ❌ 同一角色称呼连续5+行做"——"开头
- ❌ 称呼互称回声："周小姐——林先生——"死循环
- ❌ ≤3字短回声连续3+行（"嗯""好""对"）
- ❌ 同一短语5+次重复表达
- ✅ 对话占比 30-50%，废话对话 ≤30%

### 铁律2️⃣ 破折号堆 = 凑字数
- ❌ PPT分条堆：`——X。——Y。——Z。` 5+行连发
- ❌ 重复标语堆：同一短语3+次
- ❌ 思维链伪独白：内心活动5+条连续短行
- ✅ 破折号堆 ≤10处/章，全文破折号 ≤30处

### 铁律3️⃣ 剧情核对
- 写前：读前N章细纲 + 已发生事件清单
- 写中：禁用旧事件（避免重复），新事件必须可追溯
- 写后：核对时间线 + 数字单调递增
- ❌ 不能凭空加配角身世
- ❌ 不能越界角色（细纲没安排的不能登场）

### 铁律4️⃣ 字数精度
- commit前必须实测字数（`python3 -c` 或 `unified_chapter_check.py`）
- commit.msg写真实实测数字，不用粗估
- patch砍字链 ≤3次，超出切write_file
- ✅ 砍字保留：核心冲突/主角性格/伏笔埋入/章末钩子

### 铁律5️⃣ 开头7禁
- ❌ 日期开头（"X月X日 Y点"）
- ❌ "我在做什么"独白
- ❌ 数据卡/下一章预告
- ✅ 场景+人物动作开头

### 铁律6️⃣ 章末必带
```
- 第N章 完
- 末段自检：字数 / 禁项过 / 接续Ch(N-1)末 / 钩子Ch(N+1)
```

## 五、一致性架构（精简版）

### 8层防崩塌

| 层 | 名称 | 作用 |
|----|------|------|
| L1 | 角色锁 | 主角名锁定，禁止改名/编造/谐音 |
| L2 | 数值锁 | 直接引用 `设定.md`，不心算 |
| L3 | 伏笔追踪 | 写前查未回收伏笔 |
| L4 | 原文喂入 | 最近2章尾200字喂prompt |
| L5 | 字数硬约束 | 2400-3600汉字 |
| L6 | system prompt | 10条硬约束禁preamble |
| L7 | 双路径铁律 | 章节正文永远路径A（对话直写） |
| L8 | 写后审计 | `unified_chapter_check.py` 跑一遍 |

### 双路径铁律
- **路径A（永远）**：对话窗口直写 → `write_file` → 跑检查 → commit
- **路径B（禁用写章节）**：仅用于audit/调研/短摘要

## 六、三处同步 + git

```
三处真源：
  1. Riky-/novels/<书名>/     ← git真源（唯一推送）
  2. Desktop/我的网文/<书名>/   ← 用户图形界面
  3. mempalace/novel/chapters/ ← 工作副本

写章流程：
  write_file → cp同步 → cd Riky- → git add → git commit → git push

commit.msg规范：
  [末日便利店] ChN <标题> | <实测字数>汉字 | <伏笔名>
  必含：字数实测数字 / 章号 / 关键伏笔
  不写"完成"——写"产出/开坑/已写入"
```

## 七、检测器

```bash
# 单章
python3 scripts/unified_chapter_check.py chapters/末日便利店_第N章_*.md

# 批量全部
python3 scripts/unified_chapter_check.py chapters/*.md

# 全项通过后才能 commit
```

**验收铁律**：`unified_chapter_check.py` 无 FAIL → 才能 commit。
