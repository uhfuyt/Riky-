# 快速开始 · 30 分钟跑通 A 股量化引擎

这份文档带你从零跑通整条链路。**不要跳步** —— 每一步的输出都是下一步的输入。

---

## Step 0 · 环境准备（5 分钟）

```bash
python3 --version          # 需要 3.9+
pip install pandas numpy
```

或者用项目里的依赖文件：
```bash
pip install -r requirements.txt
```

**国内网络慢？换源（推荐清华）：**
```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
```

---

## Step 1 · 拉数据（5 分钟）

```bash
cd engine
python fetch_etf_kline.py
```

**它做什么**：从腾讯/新浪免费接口拉 16 只 ETF 的 750 天日线，存到 `data/`。

**你会看到**：
```
拉取 16 只ETF × 750天
[1/16] sh510300 沪深300ETF
  ✅ 750 根K线 2023-10-19 ~ 2026-11-20
```

**如果想强制刷新**（数据卡住超过 5 天时）：
```bash
python fetch_etf_kline.py --force
```

**注意**：脚本用**原子写入**（先写临时文件再 rename）。拉取失败不会破坏你已有的数据。

## Step 2 · 跑核心回测（10 分钟）⭐

```bash
cd ../scripts
python run_guosen_real_cost.py
```

**这是整个包最重要的一个脚本。** 它把**真实的 5 元最低佣金**塞进回测，回答"我这笔钱到底够不够"。

**你会看到**：
```
=== 真实费率回测 (国信: 5元最低佣金) ===
  本金      ETF收益    12窗口盈利数
  2000元   -3.28%     3/12
  5000元   -1.10%     5/12
  20000元  +2.49%     8/12
```

**如果这一步的结果是"不能做"——恭喜，你省下了几个月和几千块试错成本。**

---

## Step 3 · 验证策略稳健性（10 分钟）

```bash
python run_trend_filter_test.py   # 趋势过滤能不能救？
python run_param_robustness.py   # 参数稍微一变会不会崩？
python run_rolling_windows.py    # 滚动窗口验证
```

**这三个脚本的意义**：确认"这个策略的收益不是运气"。

`run_trend_filter_test.py` 会给你一个**反直觉**的答案：
```
趋势过滤 MA60  → 超额 33% (4/12窗口)  ← 救不了
趋势过滤 MA120 → 超额 8%  (1/12窗口)  ← 更差
趋势过滤 MA200 → 超额 0%  (0/12窗口)  ← 没用
```
**加趋势过滤不但没用，还更差。** 这就是为什么只测"有没有过滤"是不够的 —— 要测"过滤到底有没有用"。

## Step 4 · 起一个虚拟盘（持续）

```bash
cd ../engine
python etf_paper_engine.py
```

**它做什么**：每天跑一次策略，把持仓/净值/交易记录写进 `paper/` 目录，生成信号报告。

**建议**：挂个定时任务每天 15:10 跑（A 股 15:00 收盘）。

```bash
# 每天 15:10 自动跑
crontab -e
# 加入：
10 15 * * 1-5 cd /path/to/engine && python etf_paper_engine.py
```

**建议至少跑 30 个交易日再看真钱。**

---

## Step 5 · 对账（如果怀疑引擎算错）

```bash
cd ../scripts
python validate_paper_engine.py
```

用历史数据回放虚拟盘引擎，比对模拟余额和真实回测的净值曲线。
**如果对不上，说明引擎有 bug —— 先解决这个，再考虑实盘。**

## 🆘 常见报错

**`ModuleNotFoundError: pandas`**
```bash
pip install pandas numpy
```

**数据拉取失败 / 超时**
```bash
python fetch_etf_kline.py --force   # 强制重试
```
数据源是免费接口，偶尔限流是正常的。脚本有 4 次重试。

**`etf_paper_engine.py` 报 `last_date == today`**
这是**正常的** —— 当天已经跑过了。引擎是幂等的，一天只跑一次。

**回测结果和文档里的不一样**
检查 `data/` 里的数据是否完整（应该有 750 根/只）。数据被截断会显著影响结果。
