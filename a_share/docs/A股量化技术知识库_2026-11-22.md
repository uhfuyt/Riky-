## 二、A股交易成本结构（真实费率）

### 国信证券官方收费标准（用户提供截图）

| 业务类别 | 上海 | 深圳 |
|---|---|---|
| A股 | ≤3‰ **起点5元** | ≤3‰ **起点5元** |
| **证券投资基金（含LOF、ETF、封闭式基金等）** | ≤3‰ **起点5元** | ≤3‰ **起点5元** |
| 可转债、可交换债 | ≤0.2‰ | ≤1‰ |
| 港股通 | ≤2.5‰ | ≤2.5‰ |

### 蜻蜓点金（中信建投）

- 默认佣金 **万3**，单笔不足 5 元按 5 元收
- ETF 可谈到 **万0.5**，但**仍 5 元起收**
- APP 内无法自助调佣，必须联系客户经理
- 部分渠道"免五"存在，但券商客户经理明确表示**免五违规**

### 成本计算公式

```
单边成本 = max(成交额 × 佣金率, 最低佣金) + 成交额 × 滑点
往返成本 = 单边成本 × 2 + 卖出印花税(个股0.1%, ETF免)
```

**5元最低佣金占单笔金额的比例**：

| 单笔金额 | 5元占比 | 往返总成本(含滑点0.2%+印花) |
|---|---|---|
| 600元 | 0.83% | 1.97% |
| 1000元 | 0.50% | 1.30% |
| 2000元 | 0.25% | 0.80% |
| 5000元 | 0.10% | 0.50% |
| 10000元 | 0.05% | 0.40% |

**关键洞察**：要让 5 元最低佣金摊薄到"万1"水平（0.01%），单笔成交额需 **5万元**。

## 四、已验证的策略（含参数）

### 动量突破 V2 — 当前唯一通过样本外检验的策略

```python
def momentum(kline, idx):
    close = kline['收盘'].values
    high20 = close[idx-19:idx+1].max()
    ma20 = close[idx-19:idx+1].mean()
    if close[idx] > high20 * 0.998 and close[idx] > ma20:
        return 'BUY'
    if close[idx] < ma20:
        return 'SELL'
    return 'HOLD'
```

**风控参数**：止损 8% / 止盈 25% / 移动止盈 7%（跌破最高价） / 时间止损 60 交易日

## 五、⚠️ 最重要的检验：滚动窗口

**把 750 天切成 12 个不重叠的 60 交易日窗口，每个独立跑。**

| 指标 | 结果 |
|---|---|
| 策略为正 | 8/12（67%） |
| **超额为正（跑赢沪深300）** | **4/12（33%）** |
| **平均超额** | **+0.04% ≈ 0** |

**这推翻了"OOS +9.01% 很好"的表面结论** —— 那主要是 beta，不是 alpha。

**但单票满仓 = 无分散 = 单票暴雷风险。这是 5 元门槛造成的死结。**

## 七、外部技术采集（X/Twitter，2026-11-22）

用 `syndication.twitter.com/srv/timeline-profile/screen-name/<handle>` 抓取（无需API key），
共采集 81 条量化相关内容。

### 有价值的发现

**1. 因子有效性排序（@alphaarchitect 引 Robeco 样本外因子论文）**
```
✅ 有效：value（价值）、momentum（动量）、low-risk/quality（低风险/质量）
❌ 无效：size（市值）
```
→ 印证了动量是可用方向，但**样本外因子研究一致显示"没有因子能稳定跑赢"**。

**2. Sharpe ratio 的致命局限（@therobotjames）**
> "金融资产收益率并不服从正态分布，而是呈现 fat tails（肥尾）、skewness（偏度）、
> volatility clustering（波动聚集）和 leverage effects（杠杆效应）。"
>
> "Mean-variance optimisation、Sharpe ratio 和 Black-Scholes 公式
> 完全没用，不能用来赚钱。"

→ **Sharpe 0.38 / 0.71 这类数字不能作为唯一决策依据**，必须配合滚动窗口 + 超额收益检验。

**3. Kelly 准则的正确用法（@therobotjames）**
- 完整 Kelly 会带来极端回撤
- 实盘用 **Half-Kelly** 或更保守
- 参数估计误差会使 Kelly 严重高估仓位

**4. 回测-实盘同源架构（@NautilusTrader）**
> "Backtests and live trading run the same kernel: cache, message bus, data,
> execution, and risk engines. Clock and venue are pluggable, your strategy
> logic remains the same."

→ **架构原则：回测和实盘共用同一份策略代码 + 同一套执行/风控引擎**，
只切换 clock 和 venue。避免"回测一套、实盘另一套"的经典陷阱。

## 八、避坑清单（血泪）

| 坑 | 现象 | 解法 |
|---|---|---|
| **腾讯 fqkline 对 ETF 返回 501** | 任何 datalen 都 501 | 换 `/appstock/app/kline/kline` 端点 |
| **代码大小写** | `SH510300` → 501 | 统一 `.lower()` |
| **000300 歧义** | 000300=上证指数(sh)，000002=深市(sz) | 特判 000300，其余 0/2/3 → sz |
| **硬编码股票池与实际不符** | 29只里14只没数据，回测静默只跑15只，结论反转 | 每次拉完数据必须对账 |
| **Sharpe 公式错误** | `(mean*252-rf)/std*sqrt(252)` → 溢出成 96 | 应为 `(mean*252-rf)/(std*sqrt(252))` |
| **基准用指数价格** | 沪深300指数4000点，2000元买不起一手 → 基准=0 | 基准必须用**可交易的ETF真实价格** |
| **datalen 静默改小** | 640→240，窗口从2.5年腰斩，结论全翻转 | 数据窗口必须写进回测JSON元数据 |
| **只看策略收益不看超额** | OOS+9.01% 看似好，超额其实≈0 | 必须做滚动窗口 + 基准对比 |
| **低样本胜率** | 每标的1笔交易时，"胜率"=市场漂移方向 | 每策略≥100笔、每标的≥5笔才有统计意义 |
